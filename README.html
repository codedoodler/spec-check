spec-check

Keep LLM-built systems honest to their own design — before they drift.

scan → check → alert stdlib only · no deps MIT license

The problem

LLM agents can change anything at any time — including the parts you thought were settled. A system that passed its design review on Monday can silently violate it on Wednesday, because the model re-derived a value it should have fetched, or re-architected a piece it was told to leave alone.

Conventional linters and type checkers catch syntax drift. They don't catch design drift.

"Going forward let's confirm things manually rather than relying on AI entirely… we need tests for every claim, because the LLM can change anything at any time."

The big idea

1
Scan
Extract design requirements from wherever they live — architecture docs, AGENTS.md, meeting notes, conventions files.
→
2
Check
Run mechanical checks — each requirement becomes a small, deterministic check that inspects the code.
→
3
Alert
Flag regressions — when a requirement that was passing starts failing, tell a human (or an agent).

Three ways to run it

🖥️

Interactive UI

Browse requirements, run audits, filter by tier/topic/importance, see provenance, delete superseded items.

python3 server.py --root /path/to/project
🔒

Pre-commit hook

Blocks a commit when a critical (tier A/B) requirement fails. Design compliance becomes a gate, not a review.

./install-hook.sh /path/to/project
🔔

Regression alerts

The "passing Monday, failing Wednesday" signal. Flags when a requirement silently regresses, posts to Linear or a webhook.

python3 alert.py --root /path/to/project --linear-key $KEY

What a check looks like

def run(root):
    # inspect the project at `root`, return pass/fail/warn
    return [{
        "id": "D-06",
        "label": "No hard-coded magic constants in derive files",
        "tier": "D",           # A/B are critical, block commits
        "status": "fail",      # pass | fail | warn
        "detail": "0.6133 found in reasoning_plan.py"
    }]
