Design-compliance checking

spec-check

Check a codebase against its own written design requirements — before the two drift apart. LLM-built systems can change anything, at any time; this is the linter for design intent.

1The problem: silent design drift

A system passes its design review on Monday. By Wednesday it violates it — and the diff looks ordinary.

Type checkers catch syntax drift. Linters catch style drift. Tests catch behaviour in the cases you thought of. None of them read the design decision above and check it still holds.

2How it works

Turn every design decision into a checkable claim, then walk the whole list.

EXTRACT
Requirements
Parse specs, AGENTS.md, .cursorrules, [REQ] notes into what / why / check / source.
▸
CHECK
Deterministic
~10-line functions in checks/. Exact, fast, no LLM.
▸
JUDGE
LLM tier
A model reads each requirement against the code for the semantics.
▸
VERIFY
Evidence check
Cross-checks the judge; flags verdicts contradicted by the source.
▸
REPORT
Verdicts
Terminal · JSON · UI · pre-commit gate · regression alert.

3Three layers of defence

Cheap and certain first; expensive and semantic only where needed.

fastest

Deterministic checks

Rule is mechanical → a boolean over the filesystem. Runs everywhere, blocks commits, costs nothing.
semantic

LLM judge

Requirement needs judgment → a model reasons over What / Why / Check and returns verdict + evidence.
safety net

Evidence verifier

Claims "X is missing" but X is in the source? The contradiction is flagged. Catches the worst hallucination.

4What you get

Every requirement gets a verdict and, where possible, evidence. Illustrative run:

VerdictMeansEffect
passcode matches the requirement—
warnrisky, or can't be confirmednotify
failclearly violates itblock if tier A/B
unverifiableneeds a humanreport
Tier A/B failures block commits (pre-commit hook) and raise alerts. C/D are reported only.

5Three ways to run it

Interactive

python3 server.py --root …

Browse requirements with filters, sort, provenance; run an audit and overlay results on each card. :8090

Pre-commit

./install-hook.sh …

Blocks the commit when a critical requirement fails. The moment drift would otherwise enter history.

Scheduled alert

regress.py + alert.py

The “passing Monday, failing Wednesday” signal — to the terminal, a Linear ticket, or a webhook.

7Help build it

This is early, and the whole point is for others to take it further.

“Design intent can be made checkable.” That small bet is the entire project. The pieces that would make it a standard — a shared check library, a portable spec format, CI that enforces design, a benchmark for judge accuracy — do not exist yet.

If the premise is right, the interesting work is barely started.

You don’t need permission to build on this. Fork it, rename it, take the idea further than we did. The only ask: keep it honest, and keep it generic.
